# Planos

Um plano por trabalho, `AAAA-MM-DD-<assunto>.md`, escrito antes da execução e entregue pronto a quem vai executar. Este é o lugar dos planos do projeto, qualquer que seja a ferramenta que os escreve.

## O que um plano pronto tem

- **O caso:** o que força o trabalho, em palavras de quem está de fora.
- **O estado medido:** o que existe hoje, com a saída real colada.
- **Os passos numerados,** na ordem, cada um com os arquivos que toca.
- **O critério de pronto, medível:** comando e saída esperada.
- **O fora de escopo:** o que parece parte do trabalho e não é.
- **As regras do projeto** que valem para a execução (testes, commits, pastas).

Plano commitado não é plano mergeado: antes do merge ele ainda pode mudar. Depois da execução fica como registro; o que mudou no caminho vai para o [diário](../diario/).
