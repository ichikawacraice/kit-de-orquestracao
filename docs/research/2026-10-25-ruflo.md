# Ruflo × o nosso sistema de orquestração

- **Data:** 2026-10-25 (snapshot; não editar — pesquisa envelhece)
- **Autor:** P3 (planejadora, Opus 5.5), a pedido do operador via orquestradora do Izanagi
- **Objeto:** https://github.com/ruvnet/ruflo, HEAD `264b34647` (25/10/2026), npm `ruflo@3.63.0`
- **Método:** clone só-leitura no scratchpad (sem hooks de git), `gh api` e a página do npm. **Nada do ruflo foi instalado, executado ou conectado.** Toda afirmação cita arquivo:linha do clone (prefixo `r/` = raiz do repositório); o que não li está marcado como lacuna.
- **Decisões abertas:** Q229 e Q230 (no fim).

## 1. Resposta curta

**Não trocar o nosso sistema pelo ruflo.** Ele resolve outro problema: é um *harness* com centenas de tools MCP, memória vetorial e telemetria em volta de **uma** sessão do Claude Code (ou da API Anthropic). Ele não tem o que o nosso pool tem: várias sessões do app com papel fixo, uma fila com dono e travas que recusam o turno. Nenhum dos cinco defeitos medidos hoje tem conserto lá. A única ideia que pesa é pequena e encaixa no nosso: **o hook de Stop avança a fila sozinho**, em vez de esperar que o agente lembre de gravar.

### 2.1 Divisão de trabalho ("swarm", "queen", consenso)
- O pacote de enxame com Raft/Byzantine/Gossip existe (`r/v3/@claude-flow/swarm/src/consensus/raft.ts:113-126`), mas os transportes são **em processo** (`consensus/transport.ts:194-256`) e o CLI não instancia o coordenador (o único uso no cli está em `mcp-tools/capability-brain.ts:686`, que só mapeia prefixos — leitura do explorador).
- `swarm_init` grava um registro JSON (`r/v3/@claude-flow/cli/src/mcp-tools/swarm-tools.ts:261-335`, `saveSwarmStore` em `:155-160`). Não há escalonador.
- Quando um "agente" executa de fato, é **chamada direta à API Anthropic** com `ANTHROPIC_API_KEY`/`ANTHROPIC_AUTH_TOKEN` (`r/v3/@claude-flow/cli/src/mcp-tools/agent-execute-core.ts:182`, `:256`), ou o Claude Code rodando subagente `Task` a partir de um "plano de spawn" que o MCP devolve (`mcp-tools/team-tools.ts:101-132`: *"does not execute the agent"*).
- **Medido:** o "enxame" no uso real é o Claude Code lançando subagentes guiado por prompts `.md` (89 agentes e 167 comandos no cli de desenvolvimento).

### 2.2 Fila e estado
- Tarefas em `.claude-flow/tasks/store.json` (`r/v3/@claude-flow/cli/src/mcp-tools/task-tools.ts:13-15`); a descrição das tools fala em `.swarm/memory.db`, que não é o que o código grava.
- `task_assign` sem lease, heartbeat nem prazo (`task-tools.ts:461-525`); `task_complete` é **autorreportado** (`:292-316`).
- Heartbeat e fila por domínio só no `unified-coordinator.ts` do pacote swarm (~766, ~1034, ~1188), que o CLI não usa.
- **Barramento de time** (o mais próximo do nosso pool): caixa de correio em arquivo por time, com trava e escrita atômica (`r/v3/@claude-flow/cli/templates/grok/scripts/grok-team-bus.mjs`, 525 linhas). O `onStop` (`:354-385`), chamado do `SubagentStop`, marca o membro `idle`, fecha o passo do plano e devolve quem é o próximo. **É a ideia que vale absorver** (seção 4).

### 2.3 Agente preso, autopilot, laço
- O autopilot guarda `maxIterations` 50 e `timeoutMinutes` 240 (`r/v3/@claude-flow/cli/src/autopilot-state.ts:151-153`), mas nenhum Stop hook lê esse estado para reengajar (busca por `autopilot-state`/`shouldReengage` em `cli/src`; o Stop gerado só sincroniza memória: `init/settings-generator.ts:304-312`).
- O plugin `ruflo-autopilot` só aperta limites (`plugins/ruflo-autopilot/hooks/hooks.json`). **Não detecta agente parado.**

### 2.4 Contexto e memória
- Memória em SQLite WASM (sql.js) com fallback `better-sqlite3` (`memory/memory-initializer.ts:3-7`, `:229-253`); HNSW opcional (a busca cai para substring sem ele: `plugins/ruflo-cost-tracker/scripts/budget.mjs:23`).
- A própria auditoria deles achou embedding **simulado rotulado como o modelo real** e subcomandos de trajetória que não fazem nada (`r/docs/reviews/intelligence-system-audit-2026-05-29.md:44-45`, `:65-68`), e admite que o "150x–12.500x" do HNSW é inalcançável (`:120`). Os consertos estão listados no mesmo arquivo (`:98`, `:117`).
- Contexto longo: hooks `PreCompact` (`r/plugins/ruflo-core/hooks/hooks.json:64-79`) e o mod `compact`, que anexa ids do swarm ao resumo (`r/plugins/ruflo-mods/hooks/compact/block.ts:16`). **Não há limpeza de sessão nem troca de sessão.**

### 2.5 Validação e custo
- Não há verificador separado nem "truth score" no código: a palavra só aparece num ADR (`r/v3/docs/adr/ADR-322-metaharness-flywheel-integration.md:207`).
- O cost-tracker é telemetria no Stop que sempre sai 0 (`plugins/ruflo-cost-tracker/scripts/ruflo-hook.cjs:17`); `budget.mjs check` sai 1 em `HARD_STOP` (`budget.mjs:201`), mas nenhum hook o chama.
- **Lacuna:** não li o roteamento de modelo ("3-tier", Agent Booster/WASM) nem `plugins/ruflo-workflows`.

### 2.6 Integração com o Claude Code
- Três conjuntos de hooks no repositório: `r/plugin/hooks/hooks.json` (marcado `_legacy_unaudited_shim: true`), `r/.claude-plugin/hooks/hooks.json` e `r/plugins/ruflo-core/hooks/hooks.json` (PreToolUse Bash/Edit, PostToolUse, PreCompact, Stop).
- O `init` grava em `.claude/settings.json` `allow` para `Bash(npx claude-flow*)`, `Bash(npx @claude-flow*)` e `mcp__claude-flow__*` (`r/v3/@claude-flow/cli/src/init/settings-generator.ts:31-43`), e escreve `.mcp.json`, CLAUDE.md, agentes, comandos, skills e statusline (`init/executor.ts:157-224`, `:295`, `:667`).
- Os manifestos não concordam entre si nos números ("80+ agents / 100+ commands", "300+ tools", "314 MCP tools": `r/plugin/.claude-plugin/plugin.json`, `r/README.md:105`).

## 3. Segurança e cadeia de suprimento

O risco é **alto** para a nossa máquina, que roda sessões em bypass:

1. **Código novo do npm a cada ferramenta, sem versão fixa.** Sem binário `ruflo` global, cada hook de PreToolUse/PostToolUse/Stop cai em `npx --prefer-offline --yes ruflo@latest hooks …` (`r/plugins/ruflo-core/scripts/ruflo-hook.cjs:436`; shim antigo `r/plugin/scripts/ruflo-hook.sh:33`). Com 28 versões por semana e um único mantenedor no npm, a versão que roda em cada `Bash` muda sem aviso, e conta comprometida vira execução em todas as máquinas.
2. **Silêncio por desenho.** O shim manda stdout e stderr para `/dev/null` e sempre sai 0 (`ruflo-hook.sh:25`, `:37`): falha ou comportamento estranho não aparece.
3. **Veredito de permissão.** O PreToolUse escreve `{"permission":"allow"}` (`ruflo-hook.cjs:635`). É o formato do Cursor; não medi se o Claude Code o honra, mas a intenção declarada é liberar (`ruflo-hook.cjs:14`).
4. **Permissão ampla.** `mcp__claude-flow__*` libera todas as tools do servidor, entre elas tools que rodam shell, gravam disco e acessam rede (`mcp-tools/terminal-tools.ts`, `github-tools.ts`, `http-fetch-tools.ts`, `services/auto-install.ts` — presença de padrão, não auditoria). Sob bypass, `allowedTools` nem restringe (memória `allowedtools-nao-restringe-sob-bypass`).
5. **Postinstall que instala global.** `v3/@claude-flow/browser/package.json:26` roda `npm install -g agent-browser@latest` no postinstall; o do cli reescreve o `package.json` de outra dependência (`v3/@claude-flow/cli/scripts/postinstall.cjs:1-25`).
6. **Plugin de terceiro no marketplace,** puxado de outro repositório por git (`r/.claude-plugin/marketplace.json:58`, `agentic-qe`).
7. **Chave de API.** A execução própria usa `ANTHROPIC_API_KEY` (`agent-execute-core.ts:182`) — contraria a ADR 0017 do Izanagi (cada operador com a própria assinatura).

O README avisa *"Mods run with your account's permissions; review their code before installing"* (`r/README.md:44`). Revisar ~48 plugins que mudam várias vezes por dia não é viável.

## 5. O que absorver (com custo e onde)

1. **O Stop avança a fila sozinho** (ideia do `onStop`, `grok-team-bus.mjs:354-385`). Hoje o `fila-do-item.mjs` só **cobra** o membro. Proposta: no Stop do membro cujo título acabou de virar `· livre`, ou cujo item recebeu `estado: feito|aberto` no turno, o hook grava `donoLocalId: null` e o `historico` no item e a linha `parada/livre` em `sessoes`, sem depender do agente. Ataca o caso "item em execução com todas livres". **Onde:** `~/.claude/hooks/fila-do-item.mjs` (ou hook irmão) + `painel.mjs`. **Custo:** ~1 item de E, com testes no `hooks/tests/`. Encosta no F30 (P7): **conferir com ela antes** para não duplicar.
2. **Prazo no item (lease)** — o ruflo **não** tem, mas a falta dele lá mostra o buraco aqui também: item `em-andamento` cujo dono não grava há N minutos (já temos `atualizadoEm`) vira `aberto` no ritual da orquestradora, com nota. **Onde:** ritual da skill `orquestradora` + `painel.mjs list fila --vencidos`. **Custo:** pequeno.
3. **Rótulo honesto do que rodou** (a auditoria deles: mock rotulado como real, `docs/reviews/…:44`). Já é a nossa convenção *"o defeito não falha como o que é"*; nada a fazer além de citar o caso.

## 6. O que descartar, e por quê

- **Trocar o sistema inteiro:** ver seção 7.
- **Instalar qualquer plugin do marketplace deles**, inclusive só o console ou os mods: hooks em toda ferramenta com `npx …@latest`, silêncio por desenho e permissão ampla (seção 3).
- **Memória vetorial (AgentDB/RuVector):** opcional, com histórico de fallback silencioso; a nossa memória em arquivo é auditável e cabe no contexto.
- **Consenso Raft/Byzantine:** resolve concordância entre réplicas de processo; os nossos defeitos são de dono e de prazo, não de consenso.
- **Execução por API key:** contraria a ADR 0017 do Izanagi.

## 7. "Trocar tudo por ele?" — trade-offs

| | Trocar pelo ruflo | Manter e absorver 5.1–5.2 |
|---|---|---|
| Defeitos de hoje | nenhum resolvido (seção 4) | 5.1 e 5.2 atacam a fila que parece andar |
| Sessões do app com papel | não existe; viraria subagente `Task`, que o operador vetou em 23/10 (*"para ter mais controle e a orquestradora poder ver melhor"*) | existe |
| Travas que recusam o turno (critério, papel, livre-se-limpa) | não existe equivalente | existe, com testes |
| Segurança | `npx @latest` em todo hook, sob bypass | código nosso, versionado no kit |
| Custo de cota | mais processos e contexto (centenas de tools MCP no prompt) | igual a hoje |
| Custo de migrar | refazer protocolo, painel, skills e hooks; perder o histórico | ~1–2 itens de E |
| O que se ganha | ecossistema grande, console visual, muitos agentes prontos | — |

**Recomendação:** manter, absorver 5.1 e 5.2, e não instalar nada do ruflo.

## 9. Decisões para o operador
- **Q229 — trocar o nosso sistema pelo ruflo?** O caso: o ruflo é um harness em volta de uma sessão, sem sessões com papel, sem fila com dono e sem travas; nenhum dos cinco defeitos de hoje tem conserto lá, e os hooks dele baixam código novo do npm a cada ferramenta. Se não decidir: nada muda, e o estudo fica arquivado. **Recomendação:** não trocar e não instalar nada dele.
- **Q230 — absorver "o Stop solta o item e marca a sessão livre sozinho", mais o prazo no item?** O caso: hoje o hook só cobra o membro, e a fila mostrou itens "em execução" com todas as executoras livres. Se não decidir: o defeito depende do F30 e de o agente lembrar. **Recomendação:** sim, como item de executora no kit, combinado com a P7 (F30) para não duplicar.
